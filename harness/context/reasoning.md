## §2. Quality Checklist — Evidence per Criterion

Each criterion below states what was required, what was concretely done to satisfy it, and where an independent reviewer can verify the claim. Evidence is stated inline; references are used only when the evidence is too long to embed.

### C1. Distinguish 4 Rectify types without conflation

**Required:** Avoid treating CAMRectify, DEPRectify, FUTRectify, and DefaultRectify as interchangeable.

**What was done:** response.txt AI_THEORY contains a per-Rectify breakdown for THÀNH PHẦN 3 stating:
- CAM L179: `weights = pre_weights × (>OFF)`. Inactive = 0.
- DEP L304: `weights = where(pm>OFF, where(w>OFF, pm, .5pm), -.5pm)`. Negative sign = attraction.
- FUT L424: identical formula to DEP, but missing convergence filter that DEP has at L294.

The S1 ABSORBING table in response.txt explicitly lists Default ✓, CAM ✓, DEP ✓, FUT ✗ with the source line proving each.

**Verify by:** Reading rectify.py L179, L304, L424 — confirm each line matches the cited formula.

### C2. Learning-rate independent proofs

**Required:** Convergence claims must not depend on a specific learning rate value.

**What was done:** All proofs in response.txt and smap_simulator_spec.md establish gradient = 0 (absorbing) vs. gradient ≠ 0 (not absorbing) as a structural property. The reasoning pattern is:
- gradient = 0 ⟹ ∀η ≥ 0: η × 0 = 0 (no update at any learning rate)
- gradient ≠ 0 ⟹ ∀η > 0: η × g ≠ 0 (always updates)

**Verify by:** Searching response.txt and smap_simulator_spec.md for any specific η value used as a premise in a proof — none exists. Only "η > 0" is used.

### C3. Falsifiability at each step

**Required:** Every claim must specify how it could be proven wrong.

**What was done:** smap_simulator_spec.md §5 lists 6 explicit falsifiability checks:
1. Meta-state classification matches displayed rule
2. S1 gradient = 0 in CORRECT mode
3. S1 gradient ≠ 0 in CURRENT mode
4. Drift in CURRENT mode = N × |gradient| × lr
5. No drift in CORRECT mode at S1
6. Depth test discriminates correctly

The simulator's commentary (generated by `generateCommentary`) includes a "predict" line for cells where modes differ, stating: "Per-step Δ = lr × X. After N steps, divergence = N × lr × Δ. Falsify by stepping and observing."

**Verify by:** Open simulator. Select cell (2,5) in default state. Step 100 times in CURRENT mode at lr=0.01. Observe mask drift ≈ 100 × 0.01 × |gradient|. If drift differs significantly from prediction, the claim is falsified.

## §4. Verification Protocol for Independent Auditor

For an AI auditor receiving these files (response.txt, smap_simulator.jsx, smap_simulator_spec.md, this reasoning.md, plus rectify.py, smap.py, utils.py, specials.py):

**Step 1 — Read response.txt.** Identify the claims:
- 7 meta-states defined by (m, t, B)
- Unreachable (m=1, t=1, B=0)
- S1 absorbing in Default/CAM/DEP, NOT in FUT
- PART=5 fix: zVal > OFF_THRESH

**Step 2 — Verify against source code.**
- Open rectify.py. Find DEP L294 — confirm filter present.
- Find FUT L416-426 — confirm filter absent.
- This proves the structural difference.

**Step 3 — Verify simulator faithfully implements claims.**
- Open smap_simulator_spec.md §1.1 traceability table.
- For each row, check the simulator code matches the claim.
- If any mismatch — either simulator is wrong, or knowledge is wrong.

**Step 4 — Verify by execution.**
- Run simulator with default preset.
- Select cell (2, 5) — should be S1.
- In CURRENT mode: observe gradient ≠ 0.
- In CORRECT mode: observe gradient = 0.
- Step forward 50 times in CURRENT — observe drift.
- Reset, step in CORRECT — observe stability.

**Step 5 — Cross-check fix.**
- Apply proposed FUT fix to rectify.py mentally.
- Confirm: with `y_flow *= (1-case)`, at S1 (case=1), y_flow becomes 0, so Term1 = sign × weight_grdf × 0.3 × (y_flow==1 → false) × (weight>0) = 0.
- Therefore S1 absorbs after fix.

If all 5 steps produce consistent results, the analysis is verified.
